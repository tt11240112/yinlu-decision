## 第 0 章 · 30 秒搞懂三个词

不懂 Git 完全没关系，你只要知道三件事：

| 名词 | 白话 | 类比 |
|---|---|---|
| **仓库** | 装所有代码的文件夹 | 一个共享网盘 |
| **分支** | 同一份代码的不同平行版本 | 网盘里的不同文件夹 |
| **PR**（Pull Request） | "我改好了，请合并进去"的申请单 | 提交作业，等老师批 |

**我们只用两个分支**：

```
v3     ← 我们干活的地方（唯一的日常主线）
main   ← 旧版本，已永久冻结，谁都改不了（保底用，别管它）
```

---

### 2.2 每天开工前：拉最新（30 秒）

**必须先做这一步。** 不拉的话，你改的文件可能已经被人改过了，会冲突。

```
Desktop 里：右上角点 Fetch origin
           ↓
           如果变成 Pull（带数字），点它
           ↓
           变回 Fetch origin 就成了
```

**网页端**：没有"拉"的概念，网页上永远是最新，直接改就行。

---

### 2.3 改完提交：三条路线选一条

#### 🚀 路线 A · Desktop（推荐）

```
第一步：开自己的分支
   Desktop 顶部中间的分支按钮 → New branch
   命名格式：  feat/你的代号-做什么
   例如：     feat/P2-mobile-nav
              feat/P4-gaokao-filter
   ⛔ 命名里出现别的组的代号会让人困惑

第二步：改文件
   用 VS Code 打开仓库目录（Desktop 里 Repository → Open in Visual Studio Code）
   只改你名下的文件

第三步：本地先验证（改页面的必须做）
   仓库根目录双击 index.html → 浏览器打开
   F12 → Console → 确认没有红色报错
   点一遍你改的那个功能

第四步：如果动了新的 js/css 文件，或改了 template/index.html
   必须跑一次构建（否则网页上不会加载你的新文件）：
   在 VS Code 终端里执行：
       node tools/build-index.js
   ⛔ 永远不要手改根目录的 index.html —— 它是自动生成的，改了会被覆盖

第五步：提交
   Desktop 左下角 Summary 填一句话 → 点 Commit to feat/xxx
   然后右上角点 Publish branch（第一次）或 Push origin

第六步：提 PR
   Desktop 会弹出 "Preview Pull Request" → 点它 → Create pull request
   或者在网页上：仓库首页 → Pull requests → New pull request
   左边选 v3，右边选你的 feat/xxx 分支 → Create
```

#### 🌐 路线 B · 纯网页（不用装东西）

```
1. 打开仓库网页，左上角切到 v3 分支
2. 找到你要改的文件，点进去
3. 右上角的铅笔图标 ✏️ → 直接改
4. 拉到最下面，填一句话说明改了啥
5. 选 "Create a new branch for this commit" → 名字写 feat/P2-xxx
6. 点 Propose changes → Create pull request
```

> ⚠️ 网页路线改不了新增文件，也跑不了构建。
> 适合改文档、改文案。**改代码还是走路线 A。**

#### 📱 路线 C · 手机

```
装 GitHub 官方 App → 找到文件 → 右上角 ✏️ → 改 → 提交 → 提 PR
手机上不能跑构建，只适合改文档
```

### 2.4 PR 描述怎么写（照抄这个模板）

```
改了什么：
  （一句话，例如：修复筛选页在手机上按钮错位）

为什么改：
  （一句话，例如：820px 宽度下按钮会溢出屏幕）

怎么验证：
  1. 打开 index.html
  2. 浏览器窗口拖窄到 800px
  3. 点筛选按钮，确认不再溢出

影响范围：
  ☑ 只动了我名下的文件
  ☑ 本地跑过，控制台无红色报错
  ☑ 跑过 node tools/build-index.js（如果涉及新文件）
```

> **"怎么验证"必须写。** 审核的人要照着你写的步骤走一遍，不写就只能他自己猜，很慢。

---

### 2.5 提交铁律（背下来）

```
⛔ 绝不直接改 v3 分支          —— 必须开自己的分支
⛔ 绝不改别人名下的文件        —— 要改就在群里喊人
⛔ 绝不用 git add .            —— 会误加一堆文件
⛔ 绝不手改根目录 index.html   —— 它是自动生成的
⛔ 绝不引入 npm / Vite / 框架  —— 全队约定：纯静态，9 个人不用构建工具
⛔ 绝不删 legacy/ 和 main 分支 —— 那是保底
```

## 第 5 章 · 卡住了怎么办

| 症状 | 怎么办 |
|---|---|
| **不知道自己在哪个分支** | 看 Desktop 顶部中间的按钮，显示的那个就是 |
| **改了代码但网页没变化** | 浏览器 Ctrl+F5 强制刷新；还不行就是没跑 `node tools/build-index.js` |
| **改了函数但功能没变** | 全局搜函数名，可能被引擎后面的文件覆盖了（P5 的 `18` 号就被 `26` 号覆盖） |
| **控制台一堆红色报错** | 99% 是某个 JS 文件没被 index.html 引入。先跑构建脚本 |
| **PR 提示冲突** | 群里 @ 对方，两人一起解决。**不要自己强行覆盖别人的** |
| **看不到某个目录** | 资源管理器里勾上"查看 → 隐藏的项目"（`.github` 是隐藏目录） |
| **改完想反悔** | Desktop 里右键那个改动 → Discard changes。**只对你还没提交的有效** |
| **完全搞不定** | 群里 @ 全体 + 截图。**别憋着，憋着最耽误事** |
