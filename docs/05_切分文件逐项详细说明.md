## 0. 一句话结论

**切分没有改动任何一个字符，只是把一整块代码按行切成小块，放进不同文件。**

- 原来的 `app.js`（3739 行 / 247,674 字节）→ 切成 `js/01` ~ `js/26` 共 **26 个文件**
- 原来的 `styles.css`（3716 行 / 约 100KB）→ 切成 `css/01` ~ `css/15` 共 **15 个文件**
- 每个文件开头加了 5 行说明注释（描述 / 原行号 / 建议谁维护），**除此之外代码零改动**

所以：**网站的行为和切分前完全一样。** 这不是重构，是"分文件放"。

## 1. 切分到底是怎么做出来的

### 1.1 第一步：扫描原文件，找到所有"可以切"的位置

脚本（`tools/split-legacy.js`）先把 `app.js` 读进来，然后扫描每一行的开头，找出所有**顶层函数定义**的位置：

```
匹配规则：行首（可带 async）的 function 定义
  ^function xxx(
  ^async function xxx(
```

原文件里一共找到 **166 个顶层函数**。

### 1.2 第二步：按"功能语义"把连续的行归成一组

光有函数位置不够——还得知道哪一段代码是干什么的。所以脚本里手工维护了一张**行号区间表**，像这样：

```javascript
const CHUNKS = [
  [1,    26,   '01-data-experiences.js', '经验库示例数据',   'G4 数据组'],
  [27,   237,  '02-data-institutions.js','院校示例数据',     'G4 数据组'],
  [238,  379,  '03-config-constants.js', 'STORE 键名与常量', 'G0 项目组'],
  [380,  387,  '04-core-utils.js',       '$ / $$ / read...', 'G1 前端组'],
  ...
  [3658, 3739, '26-family-override.js',  '家庭功能覆盖版',   'G3 安全组'],
];
```

每一行是：`[起始行, 结束行, 新文件名, 文件描述, 建议谁维护]`。

**这张表是怎么定出来的？** 靠两件事：
1. 函数边界（不能把函数从中间切开）
2. 函数名的语义（看到 `cyberPet*` 就归到"电子宠物"，看到 `decision*` 就归到"决策日历"）

命名规则也定死了：`数字-类别-功能.js`
- 数字 = 加载顺序（**01 最先，26 最后**）
- 类别 = `data`数据 / `config`配置 / `core`核心工具 / `feature`功能模块 / `events`事件绑定 / `bootstrap`启动
- 功能 = 具体干什么

所以你看到 `10-feature-pet.js` 就知道：**第 10 个加载、是个功能模块、管电子宠物。**

### 1.3 第三步：机械切分

按区间表把行复制出来，前面加 5 行注释，写成新文件。就这一步，**没有任何代码改写**。

### 1.4 第四步：保真验证（最关键的一步）

切完必须证明"拼回去和原来一模一样"，否则就是破坏了网站。

验证做了两遍：

| 验证方式 | 结果 |
|---|---|
| 去掉每个文件的头部注释后拼回去，和原文件比对 | **完全相同** |
| 字节数对比 | 拼接 247,674 字节 = 原始 247,674 字节 |
| `diff` 命令逐行比对 | **无任何差异输出** |

CSS 用同样的方法验证，也是完全一致。

> **你完全可以自己复现这个验证**，见 `tools/split-legacy.js` 里的校验代码段。

### 1.5 第五步：生成 index.html

原来的 `index.html` 只有一行：

```html
<script src="./app.js" defer></script>
```

`tools/build-index.js` 把它替换成 26 行：

```html
<script src="./js/01-data-experiences.js" defer></script>
<script src="./js/02-data-institutions.js" defer></script>
...
<script src="./js/26-family-override.js" defer></script>
```

**这个脚本是自动扫描 `js/` 目录生成标签的**，所以以后谁新增了 `27-xxx.js`，跑一次脚本就自动加进去了，**不需要手动改 index.html**。

## 2. 文件夹各自管什么

```
引路网站_v3/
├── index.html          ← 【自动生成】网站入口，不要手改！
├── template/
│   └── index.html      ← 【HTML 源文件】要加页面/改结构，改这里
├── js/                 ← 【主要工作区】26 个 JS 文件
├── css/                ← 【主要工作区】15 个 CSS 文件
├── tools/              ← 【别动】4 个构建脚本
├── docs/               ← 【看】说明文档
├── legacy/             ← 【只读】拆分前的原始 styles.css，留着对照
├── lib/                ← 【别动】lucide 图标库（第三方）
└── *.svg               ← 8 个插画素材（宠物、图标）
```

| 文件夹 | 对应什么任务 | 谁会碰它 |
|---|---|---|
| **`js/`** | **网站的所有行为逻辑**：数据、计算、渲染、点击响应 | 全员（按认领表） |
| **`css/`** | **网站的所有外观**：颜色、间距、布局、动画 | G1 前端组为主 |
| **`template/`** | **HTML 结构源文件**——加新页面、改导航、改静态文案 | 需要加页面的人 |
| `tools/` | 自动化脚本：切分、生成 index、打包单文件版 | 只有 G0 项目组 |
| `docs/` | 团队文档 | 全员阅读 |
| `legacy/` | 拆分前的原始 CSS 备份，**只读，用来对照** | 谁都别改 |
| `lib/` | 第三方图标库 `lucide-lite.js` | 谁都别改 |
| `*.svg` | 电子宠物和引导页的插画 | G1 想换图时可以换 |

> **`index.html` vs `template/index.html` 的区别（最容易搞混）**
> - `template/index.html` = **源文件**，你要改的是它
> - `index.html` = **生成物**，跑 `node tools/build-index.js` 自动产生，手改会丢
> - 关系：`template/index.html` +（`js/` `css/` 自动注入）→ `index.html`

## 3. 最重要的一条规则：加载顺序

### 3.1 为什么顺序不能乱

这些文件**不是** ES Module（没有 `import`/`export`），而是普通的 `<script>`。浏览器从上到下依次执行：

```
01 → 02 → 03 → ... → 25 → 26
```

**后面的文件可以用前面的东西，前面的不能用后面的。**

举个具体例子：
- `04-core-utils.js` 里定义了 `$`（选择元素的快捷方式）
- `15-feature-render.js` 里大量使用 `$("#xxx")`
- 所以 **04 必须在 15 前面**

如果谁把顺序调乱了，浏览器控制台会报：
```
Uncaught ReferenceError: $ is not defined
```
然后整页功能全挂。

### 3.2 记住这个分层顺序

```
数据层   01 02        ← 静态数据（经验、院校）
配置层   03           ← STORE 键名、常量、全局状态变量
工具层   04 05        ← $ / read / write / 安全函数
功能层   06 ~ 19      ← 各个具体功能
事件层   20 ~ 24      ← 绑定点击、输入、键盘
启动层   25           ← 页面加载后执行的初始化
覆盖层   26           ← 家庭功能的改进版（必须最后）
```

**新增文件命名规则**：`27-功能名.js`、`28-xxx.js`……
数字越大越晚加载。脚本会自动扫描并按文件名排序插入。

### 3.3 一个隐藏知识点：为什么不用 import 也能互相调用

因为顶层用 `const` / `let` / `function` 声明的东西，在**所有 `<script>` 之间共享同一个全局作用域**。

```javascript
// 03-config-constants.js
const STORE = { users: "yinlu_users", ... };

// 05-core-security.js  ← 直接用，不用 import
function currentUser() { ... localStorage.getItem(STORE.users) ... }
```

好处是：**零改动迁移，不用给 26 个文件补 import 语句**（这活儿至少要一周）。
代价是：**顺序敏感、全局污染**。所以规则很简单——

> **不要新建全局变量。** 要加状态就加到 `03-config-constants.js` 的变量区，或者用现有的。

| ⚠️ 注意 | **这是"事件委托"模式：不在每个按钮上绑 onclick，而是在 document 上统一判断。** 好处是动态生成的元素自动生效；坏处是**写错 `data-` 属性名不会报错，只会"点了没反应"** |

**怎么加一个新点击行为**：
```javascript
// 1) 在 index.html 的元素上加 data- 属性
<button data-my-action="doSomething">点我</button>

// 2) 在 20-events-click.js 里加判断（放在合适的 return 之前）
const myAction = event.target.closest("[data-my-action]");
if (myAction) {
  handleMyAction(myAction.dataset.myAction);
  return;   // ← 记得 return，否则会继续往下匹配
}
```

### CSS 改法要点

**① 想改颜色但不确定在哪**：先全局搜颜色值
```bash
grep -rn "#4f7cff" css/
```

**② 主题相关的改动要动两个文件**：`04-theme-core.css`（变量定义）+ `05-theme-palettes.css`（各主题覆盖）

**③ CSS 也有顺序**：后面的覆盖前面的。所以 `05` 的配色会覆盖 `04` 的默认值——**加新主题要加在 `05` 里**

## 6. 三个必须知道的"坑"

### 坑 1：死代码（改了没效果）

因为 JS 的**同名函数后定义覆盖先定义**，而 `26` 最后加载，所以：

| 函数名 | 死代码位置 | **真正生效的位置** |
|---|---|---|
| `renderFamily` | `16-feature-compare.js:516` | ✅ `26-family-override.js:7` |
| `generateFamilyInvite` | `18-feature-actions.js` | ✅ `26-family-override.js` |
| `joinFamilyInvite` | `18-feature-actions.js` | ✅ `26-family-override.js` |

**症状**：你在 16 号文件改了 `renderFamily`，刷新页面毫无变化——因为跑的是 26 号那份。

**解决**：改家庭功能一律改 `26`。

### 坑 2：index.html 是自动生成的（要改 HTML 去 `template/`）

`index.html` 由 `tools/build-index.js` 从 `template/index.html` 生成。**手改它，下次跑脚本就被覆盖，改动全丢。**

| 你想做什么 | 改哪里 |
|---|---|
| 加新 JS 文件 | 新建 `js/27-xxx.js`，然后跑脚本 |
| 加新 CSS 文件 | 新建 `css/16-xxx.css`，然后跑脚本 |
| **加新页面 / 改导航 / 改静态文案** | **改 `template/index.html`**，然后跑脚本 |

```bash
node tools/build-index.js
```

> ⚠️ `template/index.html` 里有两行**占位符**，跑脚本时会被替换掉，**别在这两行上写东西**：
> ```html
> <script src="./app.js" defer></script>        ← 会变成 26 个 js 标签
> <link rel="stylesheet" href="styles.css">     ← 会变成 15 个 css 标签
> ```
> 其它内容（页面结构、导航、文案）都会**原样保留**到生成的 index.html 里。

### 坑 3：全局变量的隐形依赖

所有文件共享全局作用域，所以：

```javascript
// 在 27-新文件.js 里
function doSomething() {
  console.log(currentStage);   // ← 用的是 03 里的全局变量，能跑
}
```

能跑，但**危险**：你不知道别人什么时候改了它。

**规则**：
- 用现成的全局变量可以，**不要新建**
- 非要加状态，加到 `03-config-constants.js` 并在群里说一声
- 命名加前缀避免撞车，比如 `currentMyFeatureState`
