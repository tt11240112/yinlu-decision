## 一、为什么你的任务改了

之前安排你和 P1 结对做**后端服务器**（搭 Express、写 API、连数据库）。
那个计划建立在"我们还有 3 周"的假设上。

**现在院赛材料 10 月 3 日截止，只有 6 天。**

```
6 天做后端的现实结果：
   材料会来不及 → 申报书写得很潦草
   后端做不完  → 半成品，跑不起来
   = 两头都塌

所以改成：
   这次你出「数据库设计文档」（纸上设计，不写代码）
   真正的后端代码 → 11 月复赛前再做
```

**这不是降级，是换一种形式交付。** 理由：

| 理由 | 说明 |
|---|---|
| 设计文档**要交** | 它能直接进佐证 PDF，证明系统设计是完整的 |
| 设计文档**马上能用** | P1 在申报书里写"已完成数据库设计"就有底气 |
| 设计文档**不占时间** | 不用调试环境、不用学 Express，纯设计 |
| 真做起来更快 | 设计清楚了，11 月照着写两天就能出成品 |

> 📌 一句话：**先把图纸画出来，10 月 3 日交图纸；11 月再照图施工。**

## 七、怎么提交到 GitHub

你写的都是文档，**用网页直接改最省事**：

```
1. github.com 打开仓库，确认左上角是 v3
2. Add file → Create new file
3. 文件名栏填（斜杠会自动建文件夹）：
   docs/数据库设计/数据库设计说明书.md
4. 正文粘贴内容
5. 拉到最下面，选第二项 Create a new branch...
6. Propose changes → Create pull request
```

> 图片（ER 图）上传方法见 `docs/17`，或参考 P3 任务书里的说明。
