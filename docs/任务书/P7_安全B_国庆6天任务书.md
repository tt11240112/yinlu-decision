### 第 1 块（约 1 小时）· 《威胁建模表》

> **这是什么**：站在攻击者的角度，列出"这个系统可能被怎么攻击，我们怎么防"。
> 这是网安专业的看家本领，别人写不出来。

存到：`docs/安全/威胁建模表.md`

**模板**（照着填就行，填不出来就写"暂无"，也算完成）：

```markdown
# 引路系统 · 威胁建模表（STRIDE 简化版）

| # | 威胁类型 | 具体威胁 | 当前是否有防护 | 我们的做法 | 风险等级 |
|---|---|---|---|---|---|
| 1 | 仿冒（Spoofing） | 校外人员伪装在校生发布虚假经验 | 🟡 部分 | 匿名凭证 + 可信标记 | 中 |
| 2 | 篡改（Tampering） | 攻击者篡改他人分享的内容 | 🟡 部分 | 内容哈希存证 | 中 |
| 3 | 抵赖（Repudiation） | 用户发违规内容后否认是自己发的 | 🔴 无 | 待实现 | 低 |
| 4 | 信息泄露（Info Disclosure） | 用户资料存在 localStorage 明文 | 🟡 部分 | 暂不外传敏感字段 | 中 |
| 5 | 拒绝服务（DoS） | 恶意用户批量刷帖 | 🔴 无 | 频率限制（待实现） | 低 |
| 6 | 权限提升（Elevation） | 普通用户越权改他人内容 | 🟡 部分 | 前端归属校验 | 低 |
```

**六类威胁简称（STRIDE）**，记不住就直接看上面的表格列：

| 缩写 | 中文 | 一句话解释 |
|---|---|---|
| **S**poofing | 仿冒 | 冒充别人 |
| **T**ampering | 篡改 | 偷偷改数据 |
| **R**epudiation | 抵赖 | 干了不认账 |
| **I**nfo Disclosure | 泄露 | 偷看不该看的 |
| **D**enial of Service | 拒绝服务 | 把服务搞瘫 |
| **E**levation of Privilege | 提权 | 越权操作 |

> 💡 这张表**直接就能放进佐证 PDF**，而且只有网安专业写得出来。
> 它会让评委觉得"这队是真的认真想过安全问题"。

### 第 2 块（约 1.5 小时）· 《风控与合规说明》

> **这是什么**：讲清楚我们怎么处理用户的个人信息（毕竟是教育产品，会碰到学生数据）。

存到：`docs/安全/风控与合规说明.md`

**只回答这三个问题**（每问写 300–500 字就够）：

```
问题一：我们收集了用户的什么信息？
        提示：昵称、头像、意向院校/专业、发布的问答内容

问题二：这些信息存在哪里？有什么风险？
        提示：目前全部存在浏览器 localStorage 里（本地）
        好处：不出用户设备，隐私风险低
        坏处：换设备就没了，且本机可被清除

问题三：我们做了什么保护措施？接下来打算做什么？
        提示：已做/计划做的列成清单
```

> 💡 这一块也会进技术说明书。而且**这是申报书里"合规性"那一栏的答案**。

## 六、怎么提交到 GitHub

你主要写文档，**用网页直接改最省事**（不用装软件）：

```
1. 浏览器打开 https://github.com/tt11240112/yinlu-decision
2. 确认左上角分支显示的是 v3（不是就点它切换）
3. 点 Add file → Create new file
4. 文件名栏填（连斜杠一起填，会自动建文件夹）：
   docs/安全/威胁建模表.md
5. 下面正文区粘贴你写好的内容
6. 拉到页面最下面
7. 选第二项：Create a new branch for this commit and start a pull request
   （🔴 因为 v3 有保护，不能直接提交，必须走这一步）
8. 点 Propose changes
9. 下一页点 Create pull request
```

```
✅ 完成！P1 会收到通知，他会合并。
（网页会自动把 P6 加为审核人）
```
