## 4. 你这一组还缺什么（本组专属缺口）

### 🔴 最致命：没有真实院校数据，核心功能不成立

现在 `js/02-data-institutions.js` 里是**写死的示例数据**（福师大、福大、福建农林等少数几所）。

而你们产品的核心卖点是"**志愿填报决策**"——这需要：

| 缺的数据 | 说明 | 谁提供 |
|---|---|---|
| **历年录取分数线** | 至少 3 年 | G4 数据组 |
| **位次（全省排名）** | **比分数更重要**，分数每年变，位次相对稳定 | G4 |
| **招生计划人数** | 今年招多少人 | G4 |
| **专业录取分数** | 不只是学校线，还有专业线 | G4 |

**没有位次数据，"录取概率"这个功能就是编的** —— 这和我之前警告过的"编造概率是减分项"是同一个问题。

> **行动**：本周就要和 G4 对齐数据字段。你们是数据的**使用方**，G4 是**提供方**，
> 字段结构要由你们提出需求（见下面"需要你产出的一份东西"）。

### 🟠 功能缺口

| # | 缺口 | 说明 |
|---|---|---|
| 1 | **位次查询** | 输入分数 → 换算全省位次（需要一分一段表） |
| 2 | **录取概率模型** | 有了位次 + 历年数据才能算。**没有数据前别做，别编** |
| 3 | **志愿表模拟** | 冲/稳/保 三档推荐 |
| 4 | **专业对比维度不足** | 现在只能对比有限字段，应加入学科评估、保研率、就业去向 |
| 5 | **搜索体验** | 现在是简单字符串匹配，应支持拼音、别名、错别字容错 |
| 6 | **数据为空时的状态** | 搜索无结果的提示与引导（现在是空白，很难看） |

### 🟡 需要你产出的一份东西：**数据需求文档**

**这是本周你和 G4 协作的关键交付物。** 写清楚：

```
院校表需要哪些字段？
  学校名称 / 省份 / 城市 / 层次(985/211/双一流) / 类型(综合/师范/理工) / 官网 / ...

录取数据表需要哪些字段？
  年份 / 省份 / 科类(物理/历史) / 批次 / 专业 / 最低分 / 最低位次 / 招生人数 / ...

专业表需要哪些字段？
  专业名称 / 所属大类 / 学科评估 / 学制 / 学位 / ...
```

**写清楚后交给 G4-A**，他去采集数据、建库。
字段定不下来，G4 就没法干活，全组都卡住 —— **这是当前最关键的路径依赖**。
