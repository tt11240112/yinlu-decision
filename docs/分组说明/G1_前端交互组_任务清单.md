### 第 2 步：把代码下载到你的电脑

打开 GitHub Desktop → 左上角 **`File`** → **`Clone repository...`**

会弹出三个选项，点 **`URL`** 这一栏，在里面填：

```

```

下面的 **Local path（本地路径）不要改**，用默认的就行。
然后点蓝色的 **Clone** 按钮。等进度条走完（大概十几秒）。

### 第 3 步：切到正确的分支 ⚠️ 最容易漏的一步

Clonde 完之后，看 GitHub Desktop **正上方中间**，有一个写着分支名的按钮。

点它 → 在列表里选 **`v3`** → 切过去。

> **为什么**：`main` 是很早以前的旧版本（三个大文件堆在一起）。
> `v3` 才是我们切分好、你现在要用的版本。
> **没切的话，你看到的会是错的旧代码，改了也白改。**

### 第 4 步：找到你的文件

在 GitHub Desktop 里点 **`Repository`** → **`Show in Explorer`**（在文件夹里显示）。

会打开一个文件夹，里面长这样：

**你的战场就是 `js/` 和 `css/` 这两个文件夹。**

## 🔴 任务 2：跑构建命令（每次新增文件必做）

**这是最容易忘、后果最严重的一步。**

根目录的 `index.html` 是**自动生成**的。
你新增了一个 js 或 css 文件，如果不跑下面这条命令，**这个新文件根本不会被网页加载**，
你就会遇到「我明明写了代码，为什么没反应」。

在**项目文件夹里**打开终端（VS Code 里按 Ctrl + ` 反引号就能打开），执行：

```bash
node tools/build-index.js
```

看到没有报错就成功了。

> ⚠️ **千万不要手改根目录的 `index.html`**。
> 你改了之后下次任何人跑一次构建，你的改动就被冲掉了，而且很难查。
> **要改 HTML 结构，去改 `template/index.html`**，然后跑构建。

**验证构建没问题**：
```bash
node --check js/你改的文件.js     # 语法检查，没输出就是通过了
```

# 第 3 章 · 每天怎么开工、怎么提交

## 每天开工第一件事（同步别人的改动）

```bash
git checkout v3
git pull origin v3
```

> ⚠️ 注意：**不是 `pull origin main`**，是 **`v3`**。写成 main 会把旧版本拉下来，搞乱你的仓库。

## 然后开自己的分支干活

```bash
git checkout -b feat/你的名字-做什么
# 例子：git checkout -b feat/lisi-mobile-fix
```

> **分支命名规矩**：`feat/名字-做什么`。别用中文、别用空格。

## 改完提交

```bash
git add 你改的那个文件
git commit -m "style: 调整卡片间距适配手机"
git push origin feat/你的名字-做什么
```

**提交信息的开头必须写类型**，从这几个里挑：

| 类型 | 什么时候用 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修 bug |
| `style` | 改样式、改外观，不影响功能 |
| `docs` | 改文档 |
| `refactor` | 重构代码，功能不变 |
| `chore` | 杂事（改配置、删文件） |

## 最后去 GitHub 网页提 PR

1. 打开 https://github.com/tt11240112/yinlu-decision
2. 会看到一个黄色的横幅提示你有新分支，点 **Compare & pull request**
3. **⚠️ 检查右上角：`base` 必须是 `v3`**，不是 main！选错了点下拉改过来
4. 标题写清楚做了什么，正文按模板的 7 条自检填
5. Reviewers 选你的互审搭档（P2 和 P3 互相选）
6. 点 Create pull request

> **PR 合进去之后记得删分支**，不然分支会越堆越多。

# 第 5 章 · 前辈踩过的坑（看这里能省几小时）

### 坑 1：加了按钮，点了没反应

**原因**：用了事件委托（`js/20-events-click.js`）但 `data-` 属性名写错了。
写错**不会报错**，只会「点了没反应」，非常难查。

**排查办法**：在判断分支里加一行 `console.log("点到了")`，F12 看有没有输出。

### 坑 2：动态生成的按钮，绑定事件失效

**原因**：`js/23-events-buttons.js` 是直接绑在元素上的，**要求元素在页面加载时就存在**。
动态渲染出来的元素必须用 `js/20-events-click.js` 的**委托**方式。

### 坑 3：加了新弹窗，Esc 关不掉

去 `js/24-events-keyboard.js` 的 Esc 分支里，加上 `closeModal("你的弹窗id")`。

### 坑 4：加了新页面，白屏

加新页面要**四步**，漏一步就白屏：

1. 在 **`template/index.html`**（不是根目录的！）加 `<div class="view" id="view-xxx">`
2. 加导航入口
3. 需要回顶按钮的话，把 `"xxx"` 加进 `js/11-core-router.js` 的 `BACK_TO_TOP_VIEWS`
4. **跑 `node tools/build-index.js`**

> `switchView("home")` 里的名字必须和 `<div id="view-home">` 对上，写错就是白屏。

### 坑 5：改了 CSS 没效果

CSS **有加载顺序**，后面的覆盖前面的（所以 15 个文件是按文件名排序加载的）。
你的样式如果被覆盖了，可能是别的文件在后面。

找某个颜色定义在哪个文件：
```bash
grep -rn "#4f7cff" css/
```

### 坑 6：加了新主题没生效
> ① `js/03-config-constants.js` 的 `THEME_NAMES`（**这个文件是队长的，找队长改**）
> ② `css/05-theme-palettes.css` 加配色
> ③ `js/07-feature-theme.js` 加分支

### 坑 7：改新手指引文案找不到地方

文案**不在** `js/12-feature-onboarding.js`，在 **`js/11-core-router.js` 的 `ONBOARDING_STEPS`**。
