# 第 6 章 · 你自己的坑（都是踩过的）

### 坑 1：多 AI / 多来源并行改同一批文件

**出过事故**：另一个 AI 未经确认覆盖了 README.md，
写入 16 个不存在的文件名，还把安全组从 2 人砍成 1 人。

**对策**：任何工具或人改「基准文件」前，**先说明要改什么**。
改完**立刻核验**有没有被二次覆盖。

### 坑 2：CRLF 导致构建静默失效

`tools/build-index.js` 里两处正则以 `\n` 结尾。
Windows 下签出变成 CRLF → 正则失配 → **生成的 index.html 一个 CSS 都没有**，页面直接花掉，
**而且不报错，很难发现**。

已修：加了 `.gitattributes`（`* text=auto eol=lf`）+ 代码里做换行归一化。
**但这个修复必须随首次推送一起上线**，不然新 clone 的人还是会踩。

### 坑 3：打包脚本的正则没覆盖 JS 对象写法

`build-standalone.js` 的 svg 内联正则只认 `src="..."`，
但 `10-feature-pet.js` 里用的是 `src: "..."`（冒号），
导致 5 个宠物头像没被 base64 内联，**双击演示时全是空白图**。

**教训**：打包脚本正则必须覆盖 `=`、`;`、`:`、单双引号、带不带 `?v=` 后缀的所有变体。
**验收标准不是「生成成功」，而是「产物里没有明文外部引用残留」。**

### 坑 4：存在多个本地副本

曾经本机有**两个**仓库指向同一个远程，桌面那份较新，
Documents 那份（用户日常实际用的）反而落后 2 个提交。

**对策就一条**：只保留一个主目录，其余改名 `_待删_` 然后删掉。
