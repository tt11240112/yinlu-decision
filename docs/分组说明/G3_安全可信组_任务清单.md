## 🔴 任务 1：修复密码存储的算法弱点（P6，最高优先级）

**这是你们最快能拿出来、最有说服力的一个改进点。**

### 现在的问题

打开 `js/05-core-security.js` 看 `createPasswordRecord`：

```javascript
const hashBuffer = await crypto.subtle.digest('SHA-256', data);
```

它用的是 **SHA-256(salt + password)，一次哈希**。

**问题在哪**：SHA-256 是给「完整性校验」设计的，特点是**快**。
现在的 GPU 一秒钟能算**几十亿次** SHA-256。
意味着用户密码库泄露之后，**暴力破解非常便宜**。

评委只要懂一点安全，看到我们密码用 SHA-256 存，**会扣分**。

### 该怎么做

用 **PBKDF2**（Web Crypto API 原生支持，不用装任何库）：

```javascript
// 用 PBKDF2 替代单次 SHA-256
// 关键参数：iterations 迭代次数，建议 100000 以上
const keyMaterial = await crypto.subtle.importKey(
  "raw", new TextEncoder().encode(password), "PBKDF2", false, ["deriveBits"]
);
const derived = await crypto.subtle.deriveBits(
  { name: "PBKDF2", salt, iterations: 100000, hash: "SHA-256" },
  keyMaterial, 256
);
```

**验收标准**：
- [ ] 用 PBKDF2 替换掉单次 SHA-256
- [ ] 迭代次数 ≥ 100000，并且**写在可以配置的地方**（方便答辩演示时改数值讲原理）
- [ ] **老用户的密码迁移方案**：不能一改就把所有人都登不上（想想怎么平滑过渡，这是加分项）
- [ ] 在 `docs/` 里写一份《密码存储方案说明》，**说清楚为什么不用 SHA-256**

> 💡 **答辩话术储备**：
> 「我们没有使用单次哈希存储密码，而是采用了 PBKDF2 加盐派生并设置十万轮以上迭代，
> 显著提高了离线爆破成本。」—— 这句话说出来，评委知道我们是真懂的。

## 🔴 任务 2：搞清楚并写明「鉴权边界」（P6 + P7）

### 现状的事实

现在所有用户数据都存在 **localStorage**（浏览器本地）里，
`requireAuth` 也只是检查一下本地有没有登录态。

**这意味着：现在的系统其实没有真正的服务端鉴权。**

### 你们要做的**不是批判这点，而是把它讲清楚**

在 `docs/` 里写一份《安全边界说明书》，明确写：

| 问题 | 现状 | 后续规划 |
|---|---|---|
| 用户数据存哪 | 浏览器 localStorage | 迁移到服务端数据库（由 G4 后端做） |
| 鉴权在哪做 | 前端 `requireAuth` | 迁到服务端 JWT/Session |
| 目前适用什么场景 | 单机演示、原型验证 | 不能用于存储真实敏感信息 |
| 我们做了什么保护 | XSS 转义、加盐哈希、随机数、协议白名单 | 加 CSP、服务端校验、传输加密 |

> ⚠️ **这个特别重要**：答辩的时候**绝对不能吹牛说我们做了服务端加密**，
> 因为评委可能会让你打开浏览器看。**诚实讲清楚边界，反而显得专业。**
> 「这是原型阶段的纯前端方案，服务端版本在规划中」——这样说完全没问题。

## 🟠 任务 5：内容可信 / 防篡改机制（P6 + P7 合作）

这是「可信平台」最实在的一块：**用户生成的评价、提问，怎么证明没被人改过？**

**方案（从简单到复杂，选做）**：

| 方案 | 难度 | 说明 |
|---|---|---|
| **内容签名** | 低 | 每条内容生成时算一个哈希，展示时校验，改了就标「已篡改」 |
| **溯源展示** | 低 | 显示内容的产生时间、来源标识（⭐ 这个最容易做出可见效果） |
| **Ed25519 匿名凭证** | 中 | 用户能证明「我是某校学生」但**不暴露具体身份** |

> ⚠️ **做 Ed25519 请用 `tweetnacl.js` 这个成熟库，绝对不要自己手写椭圆曲线算法。**
> 自己实现密码学原语很容易写出有漏洞的东西，而且答辩被追问会很难看。
> 引入新库需要改动 `template/index.html` 的 script 标签 → **找队长**。

**信任度可视化**（配 `js/17-feature-trust.js` + `css/14-trust.css`）：
在每条评价旁边显示一个可信标识，让人一眼能看出「这个评价靠不靠谱」。

# 第 7 章 · 前辈踩过的坑

### 坑 1：改了 `js/05` 之后全站登录失效

`createPasswordRecord` 和 `passwordMatches` 是**成对**的。
改了加密方式，两个都要改，而且**已注册的老用户会因为哈希方式不同而登不上**。
→ 必须做迁移方案，或者提示用户重新注册。

### 坑 2：localStorage 里的数据被改了也没人发现

现在 localStorage 是纯明文可读写的。你在控制台敲
`localStorage.getItem('yinlu.users')` 就能看到所有用户。
**这在演示时如果被评委当场操作会很尴尬** —— 所以任务 2 的边界说明一定要写。

### 坑 3：加了 `escapeHtml` 但别处还在拼字符串

转义了但没用上的情况是白搭。审计时重点看模板字符串里的 `${变量}`。

### 坑 4：新增安全文件没跑构建，功能不生效

```bash
node tools/build-index.js      # 新增文件后必跑！
```

忘了跑的表现：新函数调不到、控制台报 `xxx is not defined`。

### 坑 5：想改 HTML 加 CSP，改错了文件

根目录的 `index.html` 是**自动生成**的，改了会被冲掉。
要改 HTML 请改 **`template/index.html`**，然后跑构建。
