## 3. 一个天然优势：数据本来就是本校的

我查了代码，示例数据里有 **16 处"福建师范大学"**：
`fjnu-cs`、`fjnu-education`、`fjnu-city`、`fjnu-campus-route`、`fjnu-data`、`fjnu-official`……
另外还有福州大学（`fzu-*`）、福建农林大学（`fafu-*`）。

**这说明示例数据本来就是围绕福州高校写的。**

### 怎么做成真数据（你们离数据源最近）

| 数据类型 | 来源 | 是否可公开使用 |
|---|---|---|
| 各专业培养方案 | 学院官网 / 教务系统 | ✅ 公开 |
| 历年录取分数线、位次 | **学校招生办公布的公开数据** | ✅ 公开 |
| 招生计划人数 | 招生办公布 | ✅ 公开 |
| 转专业政策、保研率 | 教务处文件 | ✅ 公开 |
| 校内课程体验、就业去向 | 采访本校学长学姐 | ✅ 需本人同意 |

> ### ⚠️ 数据采集的三条红线
> 1. **只用公开信息**，不要爬需要登录的系统
> 2. **不要抓个人信息**（姓名、学号、联系方式）
> 3. 采访类内容要**获得本人同意**，且能匿名就匿名
>
> 这几条也是 G3《隐私合规白皮书》要写的 —— **数据来源合规，本身就是可信度的一部分**。

## 4. 怎么用这个文件夹

### A 角：改数据的流程

1. 改 `js/01` 或 `js/02`
2. 浏览器打开看效果（**不用跑脚本**，改的是已有文件）
3. F12 确认零报错
4. 提交

### B 角：搭后端的流程

后端是**全新的目录**，建议放在仓库根目录的 `server/` 下：

```
引路网站_v3/
├── server/
│   ├── package.json
│   ├── app.js            # Express 入口
│   ├── routes/           # 路由
│   ├── db/
│   │   ├── schema.sql    # 表结构
│   │   └── yinlu.db      # SQLite 数据库文件
│   └── .env              # 配置（不要提交到 Git！）
```

**技术栈选择理由**：
- **Node.js**：和前端同一门语言，团队不用学新的
- **Express**：最简单，教程最多
- **SQLite**：**不需要装数据库软件**，一个文件就是整个数据库，最适合练手

**最小可用 API**（第一批只做这几个）：
```
POST /api/register      注册
POST /api/login         登录
GET  /api/institutions  院校列表
GET  /api/institutions/:id   院校详情
POST /api/questions     提问
GET  /api/questions     问题列表
```

**⚠️ 安全要求**（和 G3 对齐）：
- 密码**必须加盐哈希**（用 `bcrypt`），不能明文存
- 所有用户输入**必须校验**
- API 要加**鉴权**（JWT 或 session）
- 这些 G3 会检查，写进《安全测试报告》

**⚠️ 别忘了 `.gitignore`**：
```
server/node_modules/
server/.env
server/*.db
```

```
【录取数据表】
  年份 / 省份 / 科类(物理·历史) / 批次 / 专业 / 最低分 / 最低位次
  / 招生人数 / ...

【专业表】
  专业名称 / 所属大类 / 学科评估等级 / 学制 / 学位 / ...
```

> **这份文档定不下来，全组都卡住。** 这是当前**最关键的路径依赖**。

#### 2. 提交软著申请材料（配合 G0）

软著需要**源代码前 30 页 + 后 30 页 + 说明书 10–30 页**，**这主要靠你产出**：

| 材料 | 怎么来 |
|---|---|
| 源码前 30 页 | 从 `js/01` 开始导出 |
| 源码后 30 页 | 从 `js/26` 往前导出 |
| 说明书 | 从技术报告改写 |

**2026 新规**：
- 每页 **≥50 行**有效代码（页眉页脚不算）
- 用了开源组件要标注（我们用了 **lucide 图标库**）
- **版本号三处一致**（说明书、申请表、软件里）

详见 `docs/04_参赛硬性条件与软著申请.md`。

> ⚠️ **这是全项目唯一有硬性外部周期的事**（受理通知书约 5 个工作日），**本周必须提交**。

#### 4. 后端骨架跑通（B 角）

第一周目标：**能启动，能返回一条数据**。

```bash
cd server
npm init -y
npm install express sqlite3 bcrypt jsonwebtoken
node app.js
# 浏览器打开 http://localhost:3000/api/institutions 能看到 JSON
```

**不要追求完美**，先跑通一个接口，再慢慢加。

#### 5. 数据库表结构（B 角）

G2 等着这个。至少要设计：

| 表 | 主要字段 |
|---|---|
| `users` | id, 用户名, 密码哈希, 角色, 认证状态, 创建时间 |
| `institutions` | id, 名称, 省份, 城市, 层次, 类型 |
| `majors` | id, 院校id, 专业名, 大类, 学科评估 |
| `admissions` | id, 院校id, 专业id, 年份, 省份, 科类, 最低分, 最低位次, 招生数 |
| `questions` | id, 作者id, 标题, 内容, 创建时间 |
| `answers` | id, 问题id, 作者id, 内容, 创建时间 |
| `credentials` | id, 用户id, 凭证数据, 签名, 签发时间（**G3 用**） |
