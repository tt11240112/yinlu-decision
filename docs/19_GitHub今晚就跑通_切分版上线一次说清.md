# 19 · GitHub 今晚就跑通（切分版上线，一次说清）

> **面向对象**：完全没用过 Git 的队长（你）
> **目标**：让你队友能在 GitHub 上直接改代码，不用再把代码发给你手动合并
> **预计耗时**：网络正常的话 **40 分钟**
> **最后一节有"今晚我能立刻做的一步"** —— 就算断网也能做

## 零、先纠正一个误解（最重要）

你说"现在 GitHub 里只有一个超级大的代码，你不是说要切分一下嘛"。

**切分这件事，我已经做完了。就在你电脑里。**

你不需要自己动手分代码，一行都不用。`app.js` 那个 234.5 KB 的大文件，我已经拆成了 26 个小文件放在 `js/` 文件夹里；`styles.css` 那个 200.2 KB 的大文件，拆成了 15 个小文件放在 `css/` 里。

**你要做的只有一件事：把已经切好的版本，从你电脑传到 GitHub 网上去。** 这个动作叫「推送」。

## 二、⚠️ 现在的拦路虎：这台电脑连不上 GitHub

我今晚实测了三次，全挂：

| 测试项 | 结果 |
|---|---|
| `git ls-remote`（Git 访问远程） | ❌ `Could not resolve host` |
| `nslookup github.com`（DNS 解析） | ❌ 请求超时 |
| DNS 服务器地址 | `10.128.0.223`（校园网内网 DNS） |
| `curl https://github.com` | ❌ `HTTP:000`（11 秒后超时） |

**翻译成人话**：你的电脑问校园网"github.com 在哪"，校园网的 DNS 服务器不回答。找不到地址，自然连不上。

### 四种解法，按推荐顺序试

**① 手机热点（最靠谱，推荐）**

```
手机开热点 → 电脑连手机热点 → 重做推送
```

校园网经常屏蔽或解析不了境外站点，手机流量一般没问题。**这一步能解决 90% 的情况。**

**② 换个时间 / 换个网**

- 凌晨网络拥堵少，成功率更高
- 换个 WiFi（图书馆、教学楼、宿舍可能不同）
- 用舍友的手机热点交叉验证

**③ 改 DNS（有一定成功率，值得一试）**

不用改系统设置，直接在 Git Bash 里临时测：

```bash
# 测试 Google DNS 能不能解析
nslookup github.com 8.8.8.8

# 如果上面成功，说明换 DNS 有用。临时改 hosts：
# 以管理员身份打开记事本，编辑 C:\Windows\System32\drivers\etc\hosts
# 在最后加一行（IP 可能失效，届时需重新查）：
#   140.82.113.4  github.com
```

⚠️ 这招可能今天有效明天失效，作为临时手段，不要依赖。

**④ 完全断网也能做的事（今晚就能做）**

推送做不了，但**网页端的配置照样能做** —— 前提是你在能上网的设备上打开 GitHub（手机浏览器也行）。见第六节。

> 💡 **关键认知**：推送和配置是两件事。
> 配置（分支保护、邀请队友、设默认分支）在**网页上点几下**就能做。
> 推送要把文件上传。**万一只好国庆期间才能推，也不耽误你在手机上先把邀请发出去。**

## 三、推送实操（GitHub Desktop，不用敲命令）

> 前提：网络已经通了（比如连上了手机热点）

### Step 1 · 让 GitHub Desktop 认领这个仓库

1. 打开 **GitHub Desktop**
2. 左上角 **File** → **Add local repository**（添加本地仓库）
3. 路径选：`C:\Users\TT\Documents\GitHub\yinlu-decision`
4. 点 **Add repository**

> 如果它提示"这不像一个 Git 仓库"，说明路径选错了，检查是不是选到了 `yinlu-decision` 里面。

### Step 2 · 确认你在 v3 分支

看顶部中间的分支按钮，应该显示 **`v3`**。

- 如果显示的是 `main`，点它，切到 `v3`
- ⚠️ **这一步千万别搞错**：推 v3 是上线新版本，推 main 是覆盖旧版本（虽然我们不动它，但别搞混）

### Step 3 · 检查有没有没提交的东西

看左侧面板。如果写着 **"No local changes"**（没有本地变更），说明都提交干净了，可以直接推。

如果有文件列出来，说明有改动没提交：

```
左下角 Summary 填： Fix: 补充国庆文档
点 Commit to v3
```

### Step 4 · 推送 ⭐ 核心一步

看右上角的按钮，现在应该显示 **`Publish branch`**（发布分支）。

> 因为这个分支网上还没有，所以叫 Publish。以后再推送会变成 `Push origin`。

**点它。**

等待进度条走完。出现下面任一情况算成功：
- 按钮变成 `Fetch origin`（拉取）
- 顶部出现"No local changes"且历史里有 `origin/v3`

### Step 5 · 网上验证

浏览器打开 `https://github.com/tt11240112/yinlu-decision`

- 左上角分支下拉框 → 应该能看到 **`v3`** 这个选项
- 切到 v3 → 应该看到 `js/`、`css/`、`docs/`、`tools/` 这些文件夹
- 点进 `docs/任务书/` → 9 份任务书都在

✅ 到这一步，**切分版上线成功**。

### 推送失败的应急处理

| 报错 | 意思 | 怎么办 |
|---|---|---|
| `Could not resolve host` | 找不到服务器（网络问题） | 换手机热点，重来 Step 4 |
| `Authentication failed` | 登录失效 | Desktop 左上角 File → Options → Accounts → 重新登录 |
| `failed to push some refs` | 网上有你本地没有的内容 | 先点 `Fetch origin`，再 Pull，然后再 Push |
| 卡在 20% 不动 | 文件多 + 网慢 | 耐心等，或换网络重来 |

## 四、推送成功后，网页端还要做 4 件事

这 4 件事必须在网页上点，**决定了队友能不能顺畅改代码**。用电脑或手机浏览器打开 GitHub 都能做。

### ① 把默认分支改成 v3 ⭐ 最关键的隐藏项

**不做这一步的后果**：队友 clone 下来拿到的是**旧的大文件版本**，白搭。

操作：
1. 仓库页面 → **Settings**（右上齿轮）
2. 左侧 **Branches**
3. Default branch 右边点 **switch**（双箭头图标）
4. 下拉选 **`v3`** → 点 **Update**
5. 弹窗警告 → 勾 "I understand" → **Update branch**

> 改完之后，队友 clone 或者新打开仓库，默认看到的就是切分好的版本。

### ② 给 v3 上锁（防止有人乱改）

同一个 **Branches** 页面：
1. **Add branch ruleset**（新版）或 **Add rule**（旧版）
2. Branch name pattern 填 `v3`
3. 勾选：
   - ✅ **Require a pull request before merging**（必须走 PR）
   - ✅ **Require review from Code Owners** ⭐ **最容易漏，漏了 CODEOWNERS 就只是普通文字，没有任何约束力**
   - ✅ Restrict who can push → 选你（P1）和可信的人
4. ⛔ **绝对不要勾** `Require status checks to pass`
   > 我们没配自动化检查（CI），勾了之后**所有人的 PR 都会永远卡在"等待检查"，全队停摆**
5. **Create** / **Save changes**

### ③ 冻结 main（保命用）

同页面再加一条规则：
- Branch name pattern: `main`
- ✅ Restrict who can push → **只勾你自己**
- 目的：万一新手队友误操作推了旧分支，我们有完整备份

### ④ 邀请队友

1. 仓库页面 → **Settings** → **Collaborators**（协作者）
2. **Add people**
3. 输入队友的 GitHub 用户名或注册邮箱 → **Add**
4. 权限选 **Write**（可写。Admin 别给，容易误删仓库）

> 队友会收到邮件或在 GitHub 通知里看到邀请，**必须点接受才生效**。这条要在群里盯。

## 八、常见问题

**Q：推送之后，网上原来那个大文件还会消失吗？**
A：不会。`main` 分支完整保留着 `app.js`，随时能切回去看。这就是为什么我们先冻结它当保底。

**Q：队友改完我看不到？**
A：两个可能。① 他没 Push（只 Commit 了）。② 他在自己的分支上，没提 PR。让他检查 GitHub Desktop 右上角是不是显示 `Push origin`，然后再看分支名。

**Q：能不能 9 个人都在 v3 上直接改？**
A：技术上能，但等于回到"手动合并"的老路。**必须每人开自己的分支**（`feat/名字-做什么`），提 PR 再合并。这是整个协作机制的核心。

**Q：我推失败了，队友已经能 clone 网上旧版本了怎么办？**
A：没关系，先让他们 clone 旧版本练手 Git 流程。**推上 v3 之后让他们 `git pull` 一次就同步了。练手比等待重要。**

**Q：CODEOWNERS 填错了会怎样？**
A：PR 会找不到审查人，任何人都能合并，机制失效。填完先让 P2 提个练手 PR 验证。
