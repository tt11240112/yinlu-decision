## 📖 通俗理解

数据库是仓库，API 是**取货窗口**。
前端（P2/P3/P4/P5 写的页面）不直接碰数据库，而是**喊一句指令**（请求），
后端递出来（响应）。**这份文档就是规定"怎么喊、递什么"。**

---

## 一、统一约定

> 先把规矩定好，后面每个接口就不用重复解释。

| 项目 | 规定 |
|---|---|
| 请求格式 | JSON |
| 请求地址前缀 | `/api` |
| 日期格式 | ISO 8601（`2026-09-28T15:30:00Z`） |
| 认证方式 | 🔴 **找 P6 确认后填**（建议：登录返回 token，后续请求带在 header 里） |
| 成功响应 | `{ "code": 0, "data": {...} }` |
| 失败响应 | `{ "code": 4001, "message": "邮箱已被注册" }` |

**认证 header 格式**（待 P6 确认）：
```
Authorization: Bearer <token>
```

---

## 二、错误码表

> 统一错误码，前端才好判断"该怎么提示用户"。

| code | 含义 | 前端该提示什么 |
|---|---|---|
| `0` | 成功 | — |
| `4000` | 参数错误 | "请检查填写内容" |
| `4001` | 邮箱已注册 | "该邮箱已注册，请直接登录" |
| `4010` | 未登录 | "请先登录" |
| `4011` | token 过期 | "登录已过期，请重新登录" |
| `4030` | 无权限 | "你不能操作别人的内容" |
| `4040` | 数据不存在 | "内容不存在或已被删除" |
| `5000` | 服务器错误 | "服务器开小差了，稍后再试" |

## 三、接口清单

> 每个接口填一段。**示例要写真实的值**，别写 `xxx`。

### 3.1 认证

#### POST `/api/auth/register` 注册

**请求**：
```json
{
  "nickname": "小明",
  "email": "xiaoming@example.com",
  "password": "123456",
  "role": "学生",
  "stage": "高考志愿"
}
```
**成功响应**：
```json
{
  "code": 0,
  "data": { "userId": "user_xxx", "token": "..." }
}
```
**可能的失败**：`4001` 邮箱已注册 / `4000` 参数错误

---

#### POST `/api/auth/login` 登录

**请求**：`{ "email": "...", "password": "..." }`
**成功响应**：`{ "code": 0, "data": { "userId": "...", "token": "..." } }`
**失败**：`4040`（账号不存在）/ `4000`（密码错误）

---

#### POST `/api/auth/logout` 退出

**说明**：让 token 失效。
**成功响应**：`{ "code": 0 }`

---

### 3.3 问答

#### GET `/api/questions` 问题列表

**查询参数**（照 your judgment 补充）：

| 参数 | 说明 | 示例 |
|---|---|---|
| `topic` | 按话题筛选 | `?topic=志愿填报` |
| `stage` | 按阶段筛选 | `?stage=高考志愿` |
| `page` | 页码 | `?page=1` |
| `pageSize` | 每页条数 | `?pageSize=20` |

**响应**：
```json
{
  "code": 0,
  "data": {
    "total": 128,
    "list": [
      { "id": "q_1", "title": "...", "topic": "...", "status": "等待回答", "createdAt": "..." }
    ]
  }
}
```

#### POST `/api/questions` 提问

**请求**：`{ "title": "...", "content": "...", "topic": "...", "stage": "..." }`

#### GET `/api/questions/:id` 问题详情（含回答列表）

#### POST `/api/questions/:id/answers` 回答

**请求**：`{ "content": "..." }`

#### POST `/api/answers/:id/accept` 采纳答案

> ⚠️ 先去确认：**现在的采纳功能还是摆设吗？**（问 P5，翻《功能清单》）
> 如果是 🔴，这里就标注「接口已设计，**功能待实现**」。
