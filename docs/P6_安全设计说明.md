# 安全设计说明

> 引路 —— 可信的教育决策信息平台 · 技术说明书附件
> 撰写：P6（G3 安全可信组 · A 角）　日期：2026-09-27

## 1. 安全目标

平台的核心承诺是"后台实名、前台匿名、内容防篡改"。具体分解为三条：

1. **身份可信**：只有通过后台学籍核验的用户，才能获得「已验证在校生」展示标识；
2. **内容可信**：已发布的经验内容一旦被篡改，任何访问者都能验证出来；
3. **隐私最小化**：前台不暴露姓名、学号等任何实名信息，实名材料仅存于后台核验环节。

## 2. 已落地的安全机制（本次院赛前完成）

| 机制 | 位置 | 说明 |
|---|---|---|
| 密码加盐哈希 | `js/05-core-security.js` | 用户密码不落明文：24 位随机盐 + SHA-256 哈希存储，登录时重算比对 |
| 安全随机数 | `js/05-core-security.js` | 令牌/邀请码生成使用 `crypto.getRandomValues`（密码学安全随机源），不可预测 |
| 家庭邀请码校验 | `js/26-family-override.js` | `YL-XXXXXXXX` 格式：8 位字符集剔除易混淆的 0/1/I/O，正则强校验 + 全库唯一性检查 |
| 内容哈希存证 | `js/05-core-security.js`（P6 新增） | 发帖时对内容做 SHA-256 摘要存证；展示时可重新计算比对，内容被改即验不过 |
| XSS 输出转义 | 全站模板函数 | 用户输入经 `escapeHtml` 转义后再插入页面，外链经 `safeExternalHref` 白名单校验 |
| 仓库防护 | GitHub 配置 | v3 分支强制 PR + 至少 1 人审核，main 分支冻结，改动可追溯、可回滚 |

## 3. 匿名凭证体系（设计定稿，复赛实施）

采用 **Ed25519 数字签名**方案：后台核验学籍后，平台用私钥签发只含「在校生」标记的匿名凭证（不含姓名学号）；用户发帖附带凭证，前台显示徽章；任何人可用公开的平台公钥在本地验证签名真伪。签名覆盖内容摘要，实现"身份 + 内容"双重防伪。

**红线承诺**：全程不自行实现任何椭圆曲线/Ed25519 底层运算；复赛拟引入经广泛审计的 tweetnacl.js（约 10KB 纯 JS），引入前报备并经队长批准。

详细设计见《匿名凭证方案设计》（docs/P6_匿名凭证方案设计.md）。

## 4. 已知边界（诚实声明）

- 哈希存证证明"内容没被改过"，不能证明"签发者是谁"，后者由 Ed25519 签名在复赛补齐；
- 中心化签发意味着平台后台管理员理论上可作恶，复赛可探索盲签名/门限签发进一步收敛信任面；
- 纯前端 MVP 中数据存于浏览器本地存储，安全边界以"演示与方案验证"为口径，生产化需服务端签发与存储。
