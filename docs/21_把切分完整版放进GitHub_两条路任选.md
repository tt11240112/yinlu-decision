## 零、先搞明白：为什么到现在还没传上去

**不是你不会操作，是这台电脑上不了 GitHub。** 我刚才完整查了一遍：

```
DNS 解析      → 失败："本地服务器没有从权威服务器上收到响应"
HTTPS 直连    → 失败："未能解析此远程名称 github.com"
系统代理开关  → ProxyEnable = 0（关闭）
系统代理地址  → 127.0.0.1:7890（但端口无监听，说明代理软件没在跑）
```

### 💡 顺带发现一件可能有用的事

你这台机器的系统代理地址是 **`127.0.0.1:7890`**。

这个端口是 **Clash / Clash Verge 这一类代理软件的默认端口**。说明你很可能**装过**这类软件，只是现在没运行。

**如果你电脑上有这类软件（通常在右下角托盘，一个红色/蓝色的小图标）：**

```
打开它 → 开启「系统代理 / System Proxy」开关 → 回头再试推送
```

这一步可能直接解决网络问题，**比开手机热点还省事**。

> ⚠️ 我不确定你到底装没装。检查一下：任务栏右下角 ↑ 隐藏图标里找找，看有没有不认识的小图标。
> 找不到就跳过，走下面的方案。

### Step 2 · 确认在 v3 分支

看**正上方中间**那个分支按钮，必须显示 **`v3`**。

- ⚠️ **别搞混**：我们要送上去的是 v3（新的切分版），不是 main（旧的大文件版）

### Step 5 · 网上确认

### 万一报错

## 三、B 路：网页上传（不用装软件，兜底用）

> **什么时候用这条**：打不开 Desktop / 推送一直失败 / 你今天懒得折腾软件
> **原理**：就像往网盘里拖文件一样，GitHub 网页支持直接上传
> **限制**：一次最多 100 个文件 → **我们正好 100 个，要分两批**

### Step 1 · 打开仓库，确认分支

浏览器打开：`https://github.com/tt11240112/yinlu-decision`

看左上角的下拉框：

- 如果显示 **`main`** → 我们要先建 v3 分支，见 Step 2
- 如果已经有 **`v3`** → 点它切过去，跳到 Step 3

### Step 2 · 新建 v3 分支（只需做一次）

1. 点左上角那个分支下拉框（`main` 那个按钮）
2. 在搜索框里输入 **`v3`**
3. 会出现一行小字：**"Create branch: v3 from 'main'"** → **点它**
4. 页面上方的分支名就变成 `v3` 了

> 这一步的意思：从旧版本复制一条线出来，我们在新线上干活，旧线原封不动留着。

### Step 3 · 上传第一批（代码部分）

1. 点页面上那个绿色的 **`< > Code`** 标签（确保在 v3 分支）
2. 往右找 **Add file** 按钮（绿色）→ 点 → 选 **Upload files**
3. 打开**文件资源管理器**，进入：
   ```
   C:\Users\TT\Documents\GitHub\yinlu-decision
   ```
4. **拖这些文件夹到网页上**（支持拖文件夹，会自动展开里面所有文件）：

   ```
   📁 js        （26 个文件）
   📁 css       （15 个文件）
   📁 tools     （4 个文件）
   📁 template  （1 个文件）
   📁 lib       （1 个文件）
   ```
   > 小计 47 个，安全

5. 等文件名都出现在页面上（会有缩略图）
6. 滚到页面最下面，**Commit changes** 上面那个框填：
   ```
   feat: v3 模块化拆分版（代码部分）
   ```
7. 选 **`Commit directly to the v3 branch`**（直接提交）
8. 点绿色 **Commit changes**

✅ 第一批完成。页面会跳回仓库主页，能看到 `js/` `css/` 出现了。

### ⚠️ B 路的三个注意点

**① `.github` 文件夹可能被资源管理器隐藏**

`.` 开头的文件夹 Windows 默认照样显示（它不像 `.gitignore` 那样会自动隐藏），但如果你看不到：
- 资源管理器上方"查看" → 勾选 **"隐藏的项目"**

**② 不要拖 `.git` 文件夹**

那个是 Git 的内部数据库，拖上去会出问题。**只拖上面列出的那些。**

**③ 旧的 `app.js` / `styles.css` 还在**

因为 v3 是从 main 复制出来的，所以旧的大文件也跟着过来了。**先不用管**，它们不影响任何东西，还顺便当了备份。

等你熟悉了，可以在网页上逐个删掉（每个文件右上角有个垃圾桶图标）。**现在别删，容易误操作。**

## 四、上传成功后，还有 4 件事必须做

不管你走的 A 路还是 B 路，这 4 件事**缺一不可**。都在网页上点，手机也能操作。

### ① 把默认分支改成 v3 ⭐ 最关键，最容易被忘

**不做会怎样**：队友打开仓库，看到的是**旧的大文件版**，白忙。

```
仓库主页 → Settings（右上角齿轮）
        → 左侧 Branches
        → Default branch 右边点 switch（两个箭头的图标）
        → 下拉选 v3
        → Update → 勾 "I understand" → Update branch
```

### ② 给 v3 上锁

同在 Settings → Branches 页面：

```
Add branch ruleset（或 Add rule）
  Branch name pattern:  v3

  ✅ Require a pull request before merging
  ✅ Require review from Code Owners     ← ⭐ 最最重要的一个，漏了 CODEOWNERS 就是废纸
  ✅ Restrict who can push → 选你自己

  ⛔ 绝对不要勾 Require status checks
     （我们没配自动化检查，勾了全队的 PR 会永远卡住）

  Save changes
```

### ③ 冻结 main（保命）

再加一条规则：
```
Branch name pattern:  main
✅ Restrict who can push → 只勾你自己
```
目的：万一有人误操作，旧版本这个备份还在。

### ④ 填 CODEOWNERS 的用户名

你说已经把 8 个人拉进来了 —— **那现在还差最后一步**：把他们的用户名填进 `CODEOWNERS`。

现在里面有 **50 个 `<USER_G*>` 占位符**，不填的话这个文件毫无作用。

**怎么收用户名**（发群里，复制这段）：

```

1. 你的 GitHub 用户名
   （⚠️ 不是昵称！登录 github.com 后，
     点右上角头像，菜单里带 @ 的那个才是用户名）
2. 你的姓名，方便我对号入座

例：
@zhangsan123
张三
```

**怎么填**：

1. 打开 `C:\Users\TT\Documents\GitHub\yinlu-decision\.github\CODEOWNERS`
   （记事本或 VS Code 都行）
2. `Ctrl + H` 打开替换
3. 逐个替换这 8 个：

| 占位符 | 换成 | 对应谁 |
|---|---|---|
| `<USER_G1A>` | P2 的用户名 | 前端 A |
| `<USER_G1B>` | P3 的用户名 | 前端 B |

## 五、最后一步：让每人走一遍「练手 PR」（不能省）

八个人组成的团队，**最怕的就是国庆到了才发现有人不会提交**。

今晚或明晚，在群里发这段：

```
【练手任务 · 30 分钟】

目的：确认每个人都能正常提交代码，国庆前把坑踩完。

步骤：
1. 打开 https://github.com/tt11240112/yinlu-decision
2. 确认左上角显示的是 v3 分支（不是 main！）
3. 进 docs/分组说明/ 文件夹，找到你自己那份 xxx.md
4. 点右上角的铅笔图标（编辑）
5. 在文档最后一行加上：
   "已阅：<你的名字> <今天日期>"
6. 往下拉，选 "Create a new branch for this commit"
   分支名填：feat/<你的名字>-test
7. 点 Propose changes → Create pull request
8. 标题填：docs: 练手 PR

做完在群里回一声。
```

> **这一步能一次验证八件事**：有没有看到正确分支、有没有写权限、
> 会不会开分支、会不会提 PR、CODEOWNERS 有没有配对、
> 审查请求有没有自动发给对应的人。

**谁没做出来，就当场一对一教。** 国庆之后再发现，代价是十倍。
